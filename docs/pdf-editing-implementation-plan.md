# PDF ページ編集機能 引き継ぎ資料

> **PDRでの実装は中止（2026-09-06）:** PDF編集機能は別のアプリケーションで実装する。本書は、PDRで整理した要件、技術調査、実装フェーズ案、検証条件を引き継ぎ先へ渡すための資料である。PDR側の最終判断は [`pdf-editing-decision.md`](pdf-editing-decision.md) を参照。

## 1. 目的

引き継ぎ先のアプリケーションに、現在選択中のページを基準とした簡単な PDF ページ編集機能を追加する。
既存の閲覧性能を損なわず、編集結果をプレビューへ反映したうえで、元ファイルへの上書きまたは別名ファイルとして保存できるようにする。

PDRで行ったフェーズ0のコード分割はPDR内に維持するが、引き継ぎ先へ移植する対象ではない。フェーズ1では技術調査のみを行い、編集機能の製品コードは実装していない。引き継ぎ先では、自身の構成と採用ライブラリに合わせてフェーズ1以降を再評価する。

### 進捗

| フェーズ | 状態 | 備考 |
|---|---|---|
| 0 | PDRで実施済み | PDR固有のコード整理。引き継ぎ先への移植対象外 |
| 1 | PDRで調査のみ実施 | 結果を参考に、引き継ぎ先の技術構成で再確認する |
| 2〜8 | PDRでは中止 | 引き継ぎ先で実施可否と順序を決定する |

リポジトリ全体の `cargo fmt --check` は、フェーズ 0 の対象外である既存コードの整形差分も検出するため未達となっている。新規追加した `src/pdf_worker.rs` と `src/navigation.rs` は、個別の `rustfmt --check` に成功している。既存コードへ不要な整形差分を加えないため、このフェーズでは対象外の箇所を変更していない。

### 引き継ぐもの

- 2章の確定済み要件
- 4章の状態と処理フロー
- 5章のフェーズ1〜8に記載した作業、テスト、完了条件
- 6章の未決事項
- 7章の初期対象外
- 8章の検証方針

PDR固有のモジュール名、UIフレームワーク、ワーカー構成、ビルド手順は、そのまま引き継ぐ前提としない。

### 引き継ぎ先での開始手順

1. 2章の要件を、引き継ぎ先のアプリケーション仕様として採用するか確認する。
2. 6章の未決事項を決定する。
3. 採用候補の編集バックエンドについて、ライセンスと必要なページ操作を確認する。
4. フェーズ1の小規模な技術検証を、引き継ぎ先の技術構成で再実施する。
5. 検証結果をもとに、フェーズ2〜8の順序と対象範囲を確定する。

### PDRで得られた技術調査結果

- `pdfium-render 0.9.2` の公開APIには、ページ削除、ページのコピー、回転、保存に利用できるAPIがある。
- ページ移動を直接行う高水準APIは確認できなかった。
- コピーと削除でページ移動を代替する場合は、しおり、フォーム、署名などへの影響を追加検証する必要がある。
- 方針変更により、編集バックエンドの最終選定は行っていない。

## 2. 確定済みの要件

### 2.1 編集対象

- 基本の編集対象は、現在選択中の 1 ページとする。
- 見開き表示中でも、左右どちらのページが選択されているかを明示する。
- UI 上のページ番号は 1 始まり、内部のページインデックスは 0 始まりとする。

### 2.2 ページの移動

- 現在ページを 1 ページ前へ移動する。
- 現在ページを 1 ページ後ろへ移動する。
- ページ番号を指定して移動する。

### 2.3 ページの挿入

- 別の PDF ファイルを選択する。
- 選択した PDF の全ページを、現在ページの直後へ挿入する。

### 2.4 ページの削除

- 現在ページを削除する。
- ページ番号を指定して 1 ページを削除する。
- `from` と `to` を指定して、両端を含む連続範囲を削除する。

### 2.5 ページの回転

- 現在ページを右へ 90 度回転する。
- 現在ページを左へ 90 度回転する。

### 2.6 自動傾き補正

- 現在ページの数度程度の傾斜角を自動検出し、水平になるように補正する。
- 対象ページを画像化して補正し、PDF ページとして差し替える。
- 補正したページでは、文字検索、リンク、注釈などが失われる可能性がある。この制約は了承済みとする。

### 2.7 プレビューと保存

- 編集が成功した時点で、プレビューとページ番号へ反映する。
- 元 PDF への上書き保存に対応する。
- 名前を付けて保存に対応する。
- 上書き保存は `Ctrl+S`、名前を付けて保存は `Ctrl+Shift+S` を候補とする。
- 保存前の編集はメモリ上で保持し、保存操作を行うまでは元ファイルを変更しない。

## 3. PDR固有の構成と参考方針

フェーズ0の実施前は、PDRの `src/main.rs` に以下の責務が集まっていた。

- PDFium の初期化
- PDF の読み込みとページ描画
- UI と描画ワーカー間のコマンド／イベント
- ページ移動と見開き計算
- egui の画面構築と入力処理
- 描画キャッシュ管理

PDRでは、PDFiumを描画ワーカーだけから操作する設計になっている。PDRで実装する場合は、PDFの読み込み、編集、描画、保存を同じワーカーへ集約し、UIスレッドからPDFiumのオブジェクトを直接操作しない方針だった。

既存の `src/enhance.rs` は表示時の画像補正として維持し、保存を伴う自動傾き補正は別モジュールに実装する予定だった。引き継ぎ先ではこのモジュール構成を移植せず、同等の責務分離が必要かを判断する。

## 4. 引き継ぎ先で想定する状態と処理の流れ

UI 側では、少なくとも次の状態を管理する。

- 開いている PDF のパス
- 明示的に選択されているページ
- 総ページ数
- 未保存の変更があるかを示す `dirty` 状態
- 編集または保存処理中であることを示す `busy` 状態
- ページ番号／範囲入力ダイアログの状態
- 上書き確認および未保存警告の状態

編集処理は次の順序で行う。

1. UI で入力値を検証する。
2. 編集コマンドをPDF操作を担当するコンポーネントへ渡す。
3. PDF操作コンポーネントがPDFを変更する。
4. 成功イベントを受け取った場合だけページ数、選択ページ、`dirty` 状態を更新する。
5. 編集対象に関係する描画キャッシュを無効化する。
6. 現在の表示ページを再描画し、プレビューへ反映する。
7. 失敗した場合は編集前の UI 状態を維持し、原因をステータスへ表示する。

連続操作によるページ番号の競合を避けるため、編集コマンド処理中は競合する編集操作を一時的に無効化する。

## 5. 引き継ぎ先での実装フェーズ案

### フェーズ 0: PDRで実施したコード分割（参考・移植対象外）

#### 作業内容

- PDFium 初期化、ワーカーコマンド／イベント、描画処理を `src/pdf_worker.rs` へ移す。
- ページ送り、見開き構成、選択ページ計算のうち、UI に依存しない計算を独立させる。
- `src/main.rs` には `PdrApp` の状態、egui UI、入力処理を残す。
- 既存の `src/enhance.rs` は変更しない。
- 編集機能や空の編集 API は、このフェーズでは追加しない。
- `page_edit.rs` と `deskew.rs` は、それぞれ実処理を追加するフェーズで作成する。

#### 確認

- 既存 PDF の読み込み、単ページ／見開き表示、ページ送り、目次、拡大縮小、画像補正が従来どおり動作する。
- PowerShell から `cargo check`、`cargo test` を実行する。
- 新規モジュールへ `rustfmt --check` を実行する。リポジトリ全体の `cargo fmt --check` が既存箇所を検出した場合は、フェーズ 0 の差分と区別して記録する。

#### 完了条件

- 振る舞いを変えずに責務の移動だけが完了している。
- 既存テスト、追加したページ計算テスト、ビルド確認が成功している。
- 新規モジュールの整形確認が成功し、対象外の既存整形差分が記録されている。

### フェーズ 1: PDF編集・保存方式の技術検証

#### 作業内容

- 引き継ぎ先で採用候補となるバックエンドについて、PDRでの調査結果を参考に、以下の操作が可能かを小さな検証コードで確認する。
  - ページ順序の変更
  - ページ削除
  - 別 PDF からの全ページ取り込み
  - 90 度単位の回転
  - 編集済み PDF の保存
- 保存した PDF を PDFium で再度開き、ページ数と描画結果を確認する。
- 上書き時に、開いている元ファイルのハンドルが Windows 上の置換を妨げないか確認する。
- 既存機能だけで要件を満たせない場合は、追加ライブラリの必要性、ライセンス、保守性を確認してから採用可否を決定する。

採用候補のAPI、ライセンス、対応OS、保守状況は、引き継ぎ先の運用ルールに従って一次資料で確認する。

#### 完了条件

- ページ操作と保存に用いるバックエンドが決定している。
- 上書き保存を失敗時に元ファイルを壊さない手順が決定している。
- しおり、リンク、注釈、フォーム等が各操作でどう扱われるか、検証結果が記録されている。

### フェーズ 2: 選択ページと編集セッション

#### 作業内容

- 見開きの表示位置とは別に、編集対象の選択ページを管理する。
- ページ画像のクリックで選択を切り替える。
- 選択中のページに枠などの視覚的フィードバックを表示する。
- 編集メニューと、各操作の有効／無効状態を追加する。
- 開いているファイルのパス、`dirty`、`busy` を管理する。
- ページ番号入力を共通化し、1 始まりと範囲外入力を検証する。

#### 完了条件

- 単ページ表示と見開き表示の両方で、編集対象が一意に分かる。
- このフェーズでは PDF 自体の内容をまだ変更しない。

### フェーズ 3: ページ移動と削除

#### 作業内容

- ページ編集モジュールを追加し、ページ番号、削除範囲、移動後の選択位置を計算する、UIに依存しない処理を実装する。
- 現在ページの前移動／後ろ移動を実装する。
- 指定ページへの移動を実装する。
- 現在ページ、指定 1 ページ、指定範囲の削除を実装する。
- 成功後にページ数、選択位置、描画キャッシュ、目次表示を更新する。

#### テスト

- 先頭／末尾ページの移動。
- 同じ位置への移動。
- 移動元より前／後ろを指定した場合のページ番号計算。
- 範囲の両端、逆転した範囲、範囲外入力。
- 選択ページを含む範囲を削除した後の選択位置。

#### 完了条件

- 移動と削除の全操作が保存前プレビューへ反映される。
- 不正な入力では PDF が変更されない。

### フェーズ 4: 別 PDF からのページ挿入

#### 作業内容

- PDF 選択ダイアログを開き、挿入元 PDF を選択する。
- 挿入元 PDF の全ページを、現在ページの直後へ順序を維持して挿入する。
- 挿入後のページ数、選択位置、描画キャッシュを更新する。
- 読み込み失敗、0 ページ、暗号化等の処理不能な PDF では、現在の文書を変更せずエラーを表示する。

#### 完了条件

- ページ寸法や向きが異なる PDF を挿入して表示できる。
- 挿入したページを含む PDF を保存して再度開ける。

### フェーズ 5: 左右 90 度回転

#### 作業内容

- 現在ページの右 90 度回転と左 90 度回転を追加する。
- 回転後のページ寸法とアスペクト比をプレビューへ反映する。
- 同じページへの連続回転を正しく合成する。

#### テスト

- 右回転 4 回、左回転 4 回で元の向きに戻る。
- 右回転後に左回転すると元の向きに戻る。
- 縦長と横長のページで保存後の向きを確認する。

#### 完了条件

- 回転結果が即時表示され、保存後も維持される。

### フェーズ 6: 上書き保存と名前を付けて保存

#### 作業内容

- 上書き保存と名前を付けて保存を追加する。
- `Ctrl+S` と `Ctrl+Shift+S` を追加する。
- 上書き前に確認を表示する。
- 上書きでは同じディレクトリに一時ファイルを作成し、書き込みと再読込の確認後に元ファイルを置換する方式を第一候補とする。
- 失敗時は元ファイルを残し、一時ファイルの状態とエラーを明示する。
- 保存成功後に `dirty` を解除し、必要に応じて保存先を現在の文書パスにする。

#### テスト

- 別名保存後の再読込。
- 上書き保存後の再読込。
- 書き込み権限不足、使用中ファイル、無効な保存先。
- 編集していない状態での保存。

#### 完了条件

- 保存失敗時に元 PDF が破損しない。
- 保存成功後の PDF に、移動、削除、挿入、回転が反映されている。

### フェーズ 7: 自動傾き補正

#### 作業内容

- 自動傾き補正を担当するモジュールを追加する。
- 現在ページを補正用解像度で画像化する。
- グレースケール化した画像から文字列や罫線の傾斜角を探索する。
- 検出結果に信頼度を持たせ、判定不能なページを誤って回転しないようにする。
- 検出角度で画像を逆回転し、白い背景上へ配置する。
- 補正済み画像を元のページ寸法へ配置した PDF ページに差し替える。
- 処理前に、文字検索、リンク、注釈等が失われる可能性を警告する。

#### テスト

- 正負の既知角度を付けた合成文書画像。
- 傾きのない画像。
- 空白ページ、写真中心のページ、縦線中心のページ。
- 信頼度不足の場合に無変更となること。
- 補正後 PDF を保存し、再読込できること。

#### 完了条件

- 想定範囲内のスキャンページを水平化できる。
- 判定不能時はページを変更せず、理由を表示する。

### フェーズ 8: 安全性、統合確認、文書更新

#### 作業内容

- 未保存状態で別 PDF を開く場合の確認を追加する。
- 未保存状態でアプリを終了する場合の確認を追加する。
- 処理中の二重操作を防止する。
- エラー後も閲覧または再試行できる状態に戻す。
- 利用者向け文書に編集操作、ショートカット、傾き補正の制約を追加する。
- 必要な単体テストと統合テストを整理する。

#### 確認

- 引き継ぎ先で定められた整形、ビルド、テストを実行する。
- Windows 上で実際の PDF を使い、全編集操作から保存、再読込までを確認する。
- パッケージ作成は行わない。

#### 完了条件

- 通常操作、キャンセル、入力エラー、保存失敗を通して元 PDF が意図せず変更されない。
- 利用者向け文書と実際のUIが一致している。

## 6. 引き継ぎ先で実装開始前に確定する項目

以下は初期案であり、実装開始前に確認する。

1. 指定ページへの移動は「移動後に、そのページ番号になる」意味とする。
2. 全ページの削除は禁止し、最低 1 ページを残す。
3. 削除範囲で `from > to` の場合は自動で入れ替えず、入力エラーとする。
4. 挿入元 PDF のしおりは、初期実装では取り込まない。
5. 元 PDF のしおりが移動・削除後にどう更新されるかは、フェーズ 1 の検証結果をもとに決定する。
6. 自動傾き補正の初期探索範囲は ±10 度程度を候補とする。
7. 回転時の欠けを避けるため、補正画像全体を元ページ寸法内へ収め、余白を白で埋める方式を候補とする。
8. 自動傾き補正後の画像形式と解像度は、画質とファイルサイズを比較して決定する。

## 7. 初期実装の対象外

- Undo／Redo
- 複数ページの同時選択
- ドラッグ＆ドロップによる並べ替え
- 挿入元 PDF のしおりの統合
- OCR の再生成
- 自動傾き補正後の文字検索、リンク、注釈の維持
- PDF の暗号化、署名、権限設定の新規対応
- パッケージ作成とリリース

電子署名付き PDF は、内容を編集して保存すると署名の有効性へ影響するため、フェーズ 1 で検出方法と警告方法を確認する。

## 8. 検証方針

### 単体テスト

- ページ番号と範囲の検証
- 移動、削除後の選択位置
- 傾斜角検出と信頼度判定
- キャッシュ無効化対象の計算

### PDF 統合テスト

- 各ページを識別できる複数ページ PDF を用意する。
- 移動、削除、挿入、回転を組み合わせて保存する。
- 保存結果を再度読み込み、ページ数、順序、向きを確認する。
- 別名保存と上書き保存の両方を確認する。

### 手動 UI 確認

- 単ページ／見開き、左右綴じ、表紙単独の各組み合わせ。
- 見開き内のページ選択。
- 各入力ダイアログの確定とキャンセル。
- 編集直後のプレビュー、保存後の状態、未保存警告。

引き継ぎ先では、その開発環境に適した方法で自動テストを実行する。

## 9. PDR側の履歴（引き継ぎ対象外）

- フェーズ 0 の完了後に明示された指示により、プロジェクトバージョンを `0.2.0` へ更新する。
- 今回および将来のバージョン変更では、対象ファイル一覧を `docs/version-update-checklist.md` で管理する。
- スクリプト自体の確認を除き、パッケージは作成しない。
- コミット、タグ作成、プッシュは、個別に明示された場合だけ行う。
